## 3. 개발 단계에서 결정 (보류)
→ 개발 문서 [dev/](../dev/README.md)에 반영함 (v0.1 초안). 원본 7~8절을 출발점으로 하되 아래를 반영한다.
- **데이터 위치**: 원본은 제보·에피소드를 최상위에 두고 `workspaceId` 필드로 구분한다. 보안 규칙·목록 조회를 단순하게 하려면 `workspaces/{id}/…` 아래에 두는 쪽을 추천 (memorize의 `spaces/{sid}/…`와 같은 방식). 사용량·AI 작업도 워크스페이스 아래.
- **캐릭터·그림체 위치**: 원본은 캐릭터가 `episodes/{id}/characters` 아래, 그림체가 최상위에 있다. Characters·Styles 메뉴가 에피소드를 넘어 재사용되므로 워크스페이스 단위로 두고, 에피소드는 등장 캐릭터를 가리키기만 한다 (#2).
- **에피소드 상태**: 원본 `story`~`export`에 `done`(완료)·`published`(발행됨)·보관 여부 추가 ([glossary.md](./glossary.md) 3절).
- **장(page) 단위**: 원본 구조에는 컷만 있다. 장 → 컷 순서·배치를 담을 곳이 필요하다 (#8).
- **AI 작업**: 작업마다 중복 방지 키, 재시도 시 이미 받은 결과 재사용(유료 재호출 금지), 시작 전 한도 예약 → 끝나면 실제 비용으로 정산, 실패 사유 분류. 이미지 생성이 함수 실행 시간 한도를 넘을 수 있으니 트리거·작업자 방식과 타임아웃을 확인 (원본 7-3절).
- **모델 교체**: 각색·이미지 모델을 설정으로 바꿀 수 있게 공통 인터페이스 뒤에 둔다. 작업 기록에 쓴 모델·설정을 남겨 같은 조건으로 다시 생성할 수 있게 한다.
- **말풍선 렌더링**: 편집은 브라우저에서(글자·모양을 따로 저장), 최종 이미지는 같은 렌더러로 출력해 화면과 결과가 같게. 글꼴은 웹 사용·이미지 출력·상업 이용 허용 라이선스만.
- **이미지 저장**: 원본·미리보기 크기 따로, 워크스페이스별 경로와 용량 집계, 선택 안 된 후보 정리 주기.
- **제보 폼 보호**: 비회원 제출이므로 App Check + 속도 제한 + 스팸 점검. 제보자 연락처는 따로 보관하고 편집자 화면에서 가림.
- **리전**: Firestore·Functions·Storage는 서울(`asia-northeast3`) 추천. 제품별 지원 리전은 정하기 전에 확인한다.
- **비밀 정보**: AI 키는 Functions 비밀 값으로만. 4단계에 작가 키를 받게 되면 암호화 보관.
- **오류 추적·모니터링, 백업·삭제 주기, 휴지통 보관 기간**.
