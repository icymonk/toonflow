# 서비스 개요

> 상태: 초안 · v0.2 · 2026-10-19

## 1. 한 줄 정의
**썰(사연·아이디어) 하나를 넣으면 각색 → 컷 구성 → AI 그림 → 말풍선 → 인스타그램 게시용 이미지까지 한 흐름으로 만들어 주는, 1인 작가용 AI 웹툰 제작 스튜디오.**

- 슬로건: *Stories in. Comics out.* / 이야기를 넣으면, 웹툰이 완성된다.
- 핵심 약속: **창작은 당신이, 반복 작업은 TOONFLOW가.** — AI는 초안을 만들고, 무엇을 쓸지는 항상 작가가 고른다.
- 브랜드·화면 원칙은 [design/brand.md](../design/brand.md), [design/ui-system.md](../design/ui-system.md).

## 2. 배경 / 문제
- 인스타툰 한 편(보통 4~10장)을 만들려면 **썰 고르기 → 각색 → 콘티 → 작화 → 식자(말풍선) → 검수 → 게시용 출력**을 매번 반복한다. 작화·식자에 가장 많은 시간이 든다.
- AI 그림 도구를 써도 **도구가 흩어져 있다.** 글은 채팅 AI, 그림은 이미지 AI, 말풍선은 편집 앱, 파일 정리는 폴더. 프롬프트·캐릭터 설정을 매번 다시 붙여 넣는다.
- AI 그림은 **같은 캐릭터가 컷마다 달라지는** 문제가 크다. 캐릭터·그림체를 고정해 두고 재사용하는 장치가 필요하다.
- AI 그림은 **한글 글자를 제대로 그리지 못한다.** 대사는 그림과 분리해 얹어야 한다.
- 독자 제보로 만드는 썰툰은 **제보 관리·사용 동의·개인정보 제거**가 메신저와 메모에 흩어져 있다.
- 생성 비용이 **보이지 않는다.** 몇 번 다시 뽑았는지, 한 편에 얼마가 들었는지 알기 어렵다.

## 2-1. 대상
| 대상 | 원하는 것 |
| --- | --- |
| **1인 작가 · 인스타툰 크리에이터** (첫 사용자는 운영자 본인) | 썰 하나로 게시 가능한 한 편을 빨리 만든다. 그림체·캐릭터가 매번 같게 나온다 |
| **소규모 팀** (글 작가 + 그림 담당 등, 확장 이후) | 같은 작품의 캐릭터·그림체를 공유하고 나눠서 작업한다 |
| **제보자** (독자, 비회원) | 내 사연을 작가에게 보내고, 어떻게 쓰일지 동의 범위를 정한다 |

- 화면은 **데스크톱 브라우저 우선.** 태블릿은 패널을 접어서, 모바일은 제보 검토·진행 상태 확인 위주 → [design/ui-system.md](../design/ui-system.md) 6절.

## 3. 목표
1. 썰 하나를 넣어 **게시 가능한 한 편(이미지 묶음)** 까지 한 화면 흐름에서 끝낸다. (첫 수직 기능 → [roadmap.md](./roadmap.md) 1단계)
2. 각색·컷 구성·그림을 AI가 초안으로 만들고, 작가는 **고르고 고치는 데만** 시간을 쓴다.
3. 캐릭터·그림체를 한 번 등록하면 **모든 컷·모든 에피소드에서 같은 모습**으로 나온다.
4. 그림 생성은 **기다리지 않는다.** 생성 중에도 다른 컷을 편집하고, 브라우저를 닫아도 작업이 이어진다.
5. 모든 AI 작업의 **비용이 보이고, 한도를 넘지 않는다.**
6. 제보 → 동의 → 각색 → 게시까지 **누구의 어떤 사연을 어떻게 썼는지** 기록이 남는다.
7. 처음엔 혼자 쓰지만 **워크스페이스 단위**로 만들어, 다른 작가에게 열 때 다시 만들지 않는다.

## 4. 비목표 (초기 범위 밖)
- 인스타그램 **자동 게시·예약 게시** (5단계 검토). 초기엔 파일을 내려받아 직접 올린다.
- 처음부터 **그림을 직접 그리는 드로잉 도구.** 손그림 보정은 부분 수정·이미지 교체로 대신한다.
- 세로 스크롤 웹툰·출판 만화 등 **다른 형식** (5단계). 단, 브랜드와 구조는 인스타툰에만 묶지 않는다.
- 결제·요금제 (4단계).
- 스마트폰 앱 (모바일 웹으로 대응).
- 공개 갤러리·SNS 기능 (작품을 서비스 안에서 공개하는 기능).

## 6. 핵심 개념
| 개념 | 설명 |
| --- | --- |
| 워크스페이스 | 작업 공간. 작품·캐릭터·그림체·제보·사용량 한도가 모두 워크스페이스에 속한다. 처음엔 사람마다 1개가 자동으로 생긴다 |
| 썰 · 제보 | 에피소드의 재료가 되는 이야기. 독자가 보낸 **제보**와 작가가 **직접 등록**한 썰이 같은 제보함에 모인다 |
| 작품 | 같은 캐릭터·그림체를 쓰는 연재 묶음(예: "회사 생존기"). 계정 하나에 작품 여러 개 (open-questions #2) |
| 에피소드 | 게시물 한 편. 썰 하나(또는 여러 개)를 각색해 만든다. 제작 단계와 상태를 가진다 |
| 각색안 | 썰을 에피소드용 이야기로 바꾼 글(줄거리·장면·대사 초안). 버전이 여러 개 쌓이고, 하나를 "사용 중"으로 고른다 |
| 장 | 게시물의 이미지 한 장(인스타그램 캐러셀의 한 장). 장 안에 컷이 1개 이상 |
| 컷 | 그림 한 칸. 장면 설명·등장 캐릭터·대사·연출을 가지고, 이미지 후보를 여러 개 가진다 |
| 후보 | 한 컷에 대해 AI가 생성한 이미지 하나. 작가가 하나를 **선택**하면 그 컷의 그림이 된다 |
| 그림체 | 공통 화풍 설정(설명·참조 이미지·색감·금지 요소). 작품마다 기본 그림체를 정한다 |
| 캐릭터 | 이름·외형·성격·말투·참조 이미지. 컷에 등장시키면 그림 생성 때 함께 전달된다 |
| AI 작업 | 각색·컷 나누기·이미지 생성처럼 AI를 부르는 일 하나. 대기열에서 진행 상태·비용·실패 사유가 보인다 |
| 사용량 한도 | 워크스페이스가 한 달에 쓸 수 있는 AI 비용(또는 크레딧) 상한 |

## 7. 핵심 흐름 (제작실 5단계)

| 단계 | 작가가 넣는 것 | AI가 하는 것 | 작가가 정하는 것 | 다음 단계로 넘어가는 조건 |
| --- | --- | --- | --- | --- |
| **Story** 각색 | 썰, 톤, 목표 장 수, 작품 | 썰 요약·핵심 포인트, 각색안 1~3개 | 사용할 각색안, 직접 수정 | 사용 중 각색안이 있음 |
| **Storyboard** 콘티 | (각색안) | 장·컷 나누기, 컷마다 장면·캐릭터·대사 초안 | 컷 순서·대사·연출 확정 | 모든 컷에 장면 설명이 있음 |
| **Illustrate** 작화 | (컷, 캐릭터, 그림체) | 컷마다 이미지 후보 생성, 부분 수정 | 컷마다 후보 하나 선택 | 모든 컷에 선택된 이미지가 있음 |
| **Review** 검수 | (선택 이미지 + 대사) | 말풍선 자동 배치 초안, 개인정보·오탈자 점검 | 말풍선 위치·글꼴, 검수 체크 | 필수 검수 항목 통과 |
| **Export** 출력 | 캡션·해시태그 | 캡션 초안 | 출력 규격, 파일 내려받기 | 내려받기 또는 발행 기록 |

- 단계는 **앞뒤로 자유롭게 오갈 수 있다.** 앞 단계를 고치면 뒤 단계에 "영향 받음" 표시만 하고, 이미 만든 결과를 지우지 않는다 → [features/studio.md](../features/studio.md) STU-12.
- 첫 개발 목표는 이 5단계를 **가장 얇게라도 끝까지** 잇는 것 → [roadmap.md](./roadmap.md) 1단계.

## 8. 리뷰 질문
- 첫 사용자는 본인(운영자)이 맞는가? 처음부터 함께 쓸 사람(지인 작가 등)이 있는가?
- 인스타툰 한 편의 보통 분량(장 수, 장당 컷 수)은 어느 정도인가? 기본값을 정하는 데 쓴다.
- 손그림·직접 그린 캐릭터 이미지를 섞어 쓸 계획이 있는가? (컷 이미지 직접 올리기 ILL-30의 우선순위)
